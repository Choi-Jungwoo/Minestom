# Experimental native Bedrock adapter

The `bedrock` module accepts Bedrock clients directly over UDP/RakNet and admits
them as ordinary Minestom `Player` instances. It is an optional repository
module: Java-only applications do not receive Cloudburst, RakNet, Netty native
transport, or mapping dependencies.

The module remains experimental and is not published to Maven Central while its
pinned Cloudburst dependencies require the OpenCollab repository. It does not
start with the Java listener automatically.

## Starting the listener

The following is a complete server configuration for a source checkout that
includes `implementation(project(":bedrock"))`:

```java
import net.minestom.server.Auth;
import net.minestom.server.MinecraftServer;
import net.minestom.server.ServerProcess;
import net.minestom.server.bedrock.BedrockServer;
import net.minestom.server.bedrock.BedrockServerConfig;
import net.minestom.server.instance.InstanceContainer;
import net.minestom.server.instance.block.Block;

import java.net.InetSocketAddress;
import java.nio.file.Path;
import java.util.Objects;

public final class BedrockExample {
    public static void main(String[] arguments) {
        MinecraftServer minecraftServer = MinecraftServer.init(new Auth.Offline());
        ServerProcess process = Objects.requireNonNull(MinecraftServer.process());
        InstanceContainer instance = process.instance().createInstanceContainer();
        instance.setGenerator(unit -> unit.modifier().fillHeight(0, 40, Block.STONE));

        var config = new BedrockServerConfig(
                new InetSocketAddress("0.0.0.0", 19132),
                instance,
                Path.of("run/bedrock-mappings"));
        BedrockServer bedrockServer = BedrockServer.create(process, config);
        bedrockServer.start();

        minecraftServer.start("0.0.0.0", 25565);
    }
}
```

UDP may use the same numeric port as the Java TCP listener. `stop()` is
idempotent, and process shutdown also stops the listener and owned sessions.
Only one `BedrockServer` may own a `ServerProcess`.

## Compatibility policy

- **Supported:** protocol 1001 / Bedrock wire version 1.26.30, backed by the
  Bedrock 1.26.30.5 to Java 26.2 mappings and the automated compatibility suite.
- **Accepted experimentally:** protocols 924, 944, 975, and 2168. Their
  Cloudburst codecs can safely decode the wire format, but the baseline mappings
  and promised gameplay suite do not establish compatibility.
- Protocols outside the available Bedrock 1.26.x codecs are rejected before
  player admission. Discovery always advertises the primary supported protocol,
  never the codec selected by an experimental client.

Run `mise run bedrock-compatibility` to print every immutable dependency,
mapping, and protocol pin. The same values are recorded in
`META-INF/minestom-bedrock.properties`.

## Feature support matrix

| Capability | Status | Limits |
| --- | --- | --- |
| UDP discovery and protocol selection | Supported | Discovery advertises protocol 1001 |
| Offline self-signed or guest login | Supported | Not proof of an online Microsoft account |
| Encryption, compression, empty resource-pack handshake | Supported | Custom resource packs are not supported |
| StartGame and initial world loading | Supported | Requires the exact verified mapping bundle |
| Chunks, unloads, block updates, basic movement | Supported | Advanced movement capabilities are rejected |
| Position correction, teleport, Instance change | Supported | Full death/respawn is not supported |
| Multiple player visibility and basic equipment | Supported | Non-player entities are not supported |
| Classic Bedrock skins and generated Java fallback | Supported | Persona skins are rejected |
| Ordinary chat and slash-command execution | Supported | No signed-chat guarantee or command tree/completion |
| Latency, kick, disconnect, transfer, shutdown | Supported | Stable client reasons hide internal failures |
| Inventory transactions, containers, interactions | Not supported | No crafting, block use, or entity interaction |
| Online Xbox/Microsoft authentication | Not supported | Offline identity only |

Passing the automated suite does not claim support for non-player entities,
command-tree completion, Persona skins, or online account authentication.
Official-client manual testing is useful but is not a release gate.

## Mapping sources and gate

The supported bundle has two immutable inputs:

| Input | Source revision | SHA-256 |
| --- | --- | --- |
| Geyser mappings for Java 26.2 / Bedrock 1.26.30.5 | `GeyserMC/mappings@47949016f0079578a9e979c93a2b3765354235ea` | `92c1d3bc5b12705d20290363857a19ea202a88bdc5f79f560ead8b345442cbd0` |
| `block_palette.26_30.nbt` | `GeyserMC/Geyser@0dbc38fa6ff1d9c4610b5218a3ae1fbacc77c092` | `73ef6dadfa16dd52319493c8112ecb13a020989cf04452f76ff4a8a250a29fea` |

The mappings are generated by the maintained
[`GeyserMC/mappings-generator`](https://github.com/GeyserMC/mappings-generator).
Its upstream workflow uses `runMappings`/`runDatagen` and requires manual review
of warnings and incomplete mappings.

Mapping data is not bundled until the project records explicit redistribution
approval for data that Geyser cannot relicense on behalf of Mojang or Microsoft.
Until then, each operator must acquire the pinned inputs and supply the verified
directory. Do not commit, publish, or mirror the prepared directory.

One reproducible preparation flow is:

```shell
git clone https://github.com/GeyserMC/mappings.git /tmp/minestom-mappings
git -C /tmp/minestom-mappings checkout --detach \
  47949016f0079578a9e979c93a2b3765354235ea
curl --fail --location \
  https://raw.githubusercontent.com/GeyserMC/Geyser/0dbc38fa6ff1d9c4610b5218a3ae1fbacc77c092/core/src/main/resources/bedrock/block_palette.26_30.nbt \
  --output /tmp/minestom-mappings/block_palette.26_30.nbt
mise run bedrock-mappings-verify /tmp/minestom-mappings
mise run bedrock-mappings-prepare \
  /tmp/minestom-mappings run/bedrock-mappings
```

Preparation refuses an existing destination, copies only the required regular
files without following symbolic links, and verifies the destination again.

For an update:

1. Select fixed Geyser mappings, Geyser runtime-palette, Cloudburst, RakNet, and
   Netty revisions; never use `latest` or a floating snapshot.
2. Generate or obtain the mapping output, review generator warnings, licenses,
   registry coverage, and the corresponding Bedrock codec.
3. Compute the aggregate mapping checksum and palette checksum, then update
   `BedrockCompatibility`, `minestom-bedrock.properties`, this document, and the
   compatibility tests in one change.
4. Run `mise run bedrock-mappings-verify`, `mise run bedrock-acceptance`, and
   `mise run check`.
5. Mark a codec supported only after matching mappings and the full automated
   acceptance suite pass. Keep it merely accepted otherwise.
6. Obtain and record redistribution approval before embedding or redistributing
   any new bundle.

## Verification

- `mise run check` runs all module tests, formatting/static checks, and the
  tagged real-UDP Bedrock acceptance suite.
- `mise run bedrock-acceptance` runs discovery, exact codec negotiation, offline
  login, StartGame/resource packs, world loading, movement/teleport, multiplayer,
  chat/commands, transfer, disconnect, and the accepted-versus-supported gate.
- `mise run bedrock-check` runs the complete Bedrock module verification.
- `mise run bedrock-mappings-verify <directory>` validates release identity,
  both checksums, required regular files, NBT/JSON structure, and critical
  registry coverage.

## Operations

### Ports and lifecycle

- Open the configured UDP port (normally 19132) in host and network firewalls.
  A TCP rule alone is insufficient.
- Start the listener explicitly after constructing the spawning `Instance`.
- Stop through the normal Minestom process lifecycle. Shutdown stops admission,
  disconnects sessions, removes players, closes the UDP channel, and terminates
  owned event-loop threads.
- A bind failure usually means another UDP listener owns the address or the
  process lacks permission.

### Capacity and rate limits

`BedrockServerLimits.defaults()` permits 1,024 concurrent connections and 20
connection attempts per source address per second. It also bounds RakNet MTU,
uncompressed packets (1 MiB), compressed batches (2 MiB), decompressed batches
(8 MiB), inbound packets per connection/tick (256), and combined login JWT data
(1 MiB). Classic skins are limited to 64 pixels wide, 32 or 64 pixels high.

Choose lower application-specific values with
`BedrockServer.create(process, config, limits)` when memory, CPU, or upstream
bandwidth is constrained. Rate limiting is a safety boundary, not a substitute
for network-layer DDoS protection.

### Logs and privacy

Protocol diagnostics are rate-limited and include protocol, Bedrock state,
packet type, and a server-side root cause. Client-visible failures use stable
reasons without internal details.

Offline login verifies JWT structure, signatures, expiry, and client-data
integrity but does not prove Microsoft account ownership. Raw JWTs, certificate
chains, XUID, device identifiers, and other unnecessary identity material are
discarded after admission and must not be added to logs. Only bounded derived
profile and classic-skin data may remain.

### Native transport

NIO is always the fallback. Epoll on Linux and kqueue on macOS/BSD are selected
only when Netty reports their matching native runtime as available. Applications
that want a native transport must add the matching Netty native artifact at the
module's pinned Netty version and verify the classifier for the deployment
architecture. `mise run bedrock-check` exercises the available transport and
class linkage.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Server is absent from discovery | UDP firewall/NAT, bind address, advertised port, and listener running state |
| Startup reports missing or changed mappings | Use the exact revisions above; run `bedrock-mappings-verify` before startup |
| Experimental client decodes but disconnects in world loading | Its codec is accepted, not supported; do not infer mapping compatibility |
| Login is rejected | Client name length, JWT expiry/signatures, classic skin bounds, Persona flag, and configured JWT limit |
| Movement disconnects | Unsupported movement capability or per-tick packet limit |
| Native transport falls back to NIO | Matching native artifact/classifier is absent or unavailable; NIO remains supported |
| Shutdown leaves a port busy | Ensure the owning `ServerProcess` stopped and no second process owns the UDP port |
| Logs omit a raw client cause | Expected privacy behavior; use the structured server-side diagnostic fields |
